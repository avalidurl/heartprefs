IANA Media Type Registration — application/vnd.heartprefs+json
Template per RFC 6838 §5.6 (+json structured syntax suffix per RFC 6839).
Prepared 2026-07-04. Vendor tree (see note under "Restrictions on usage").

Type name:
   application

Subtype name:
   vnd.heartprefs+json

Required parameters:
   N/A

Optional parameters:
   N/A

Encoding considerations:
   binary.  A HeartPrefs document is a JSON text as defined in RFC 8259 and
   therefore MUST be encoded in UTF-8.  Same considerations as application/json
   (RFC 8259) and the "+json" structured syntax suffix (RFC 6839).

Security considerations:
   A HeartPrefs document is passive data; it contains no executable content and
   MUST NOT be interpreted as such.  General JSON security considerations
   (RFC 8259 §12) and "+json" suffix considerations (RFC 6839 §3.1) apply.

   Documents are cryptographically signed: the "proof" member is a detached
   signature over the RFC 8785 (JCS) canonicalization of the document with the
   signature removed, and MUST verify by recovering the signer and asserting it
   equals the DID in "identity.subject".  Consumers MUST treat a document whose
   signature does not recover to its subject as invalid.

   HeartPrefs documents describe personal matching preferences and MAY reference
   verifiable credentials.  Adulthood is conveyed by selective disclosure of a
   boolean predicate ("ageOver18") — implementations MUST NOT include a date of
   birth or other unnecessary personal data.  Some fields ("desire",
   "boundaries") are gated and MUST be withheld until identity proof and
   payment/consent are satisfied.  Transport confidentiality (TLS) is
   RECOMMENDED whenever documents are exchanged.

Interoperability considerations:
   The document shape is defined by a versioned JSON Schema (draft 2020-12)
   identified by its "$id".  The top-level "version" member carries the document
   semver.  Processors that do not recognize a version SHOULD reject rather than
   guess.

Published specification:
   HeartPrefs Specification v0.1 (DRAFT):
   https://github.com/gokhan-vc/heartprefs/blob/main/spec/0.1/SPEC.md
   JSON Schema: https://raw.githubusercontent.com/gokhan-vc/heartprefs/main/spec/0.1/heartprefs.schema.json

Applications that use this media type:
   Agent-mediated matching / dating venues and the agents that act for their
   users; tooling that builds, signs, validates, or exchanges portable
   matching-intent documents over x402, A2A Agent Cards, MCP resources, or
   ERC-8004 service entries.

Fragment identifier considerations:
   Same as for "application/json" per RFC 6839 §3.1: a JSON Pointer
   (RFC 6901) MAY be used to identify a specific value within the document.

Restrictions on usage:
   None.  Note: this registration is in the VENDOR tree
   ("application/vnd.heartprefs+json") because HeartPrefs is not (yet) on a
   recognized standards-body track (RFC 6838 §3.2).  Upon adoption by the
   HeartPrefs W3C Community Group it MAY be re-registered in the standards tree
   as "application/heartprefs+json".
